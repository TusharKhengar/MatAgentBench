**Where do LLM agents actually break when they run real atomistic materials workflows —
and can we prove it?**

MatAgentBench is a verifiable benchmark plus a *counterfactual failure-attribution
harness* for agents doing computational materials science: fetch a crystal structure,
relax it with a machine-learned interatomic potential, compute a property, report it.

It is built around one claim that most agent evaluations cannot make:

> When an agent fails here, we can usually name the cause — and prove it by repairing
> exactly that cause and re-running.

**Reproducible end to end at zero cost.** Open-weight models on free API tiers, ML
interatomic potentials instead of DFT, and CC-BY / public-domain ground truth. No
frontier API budget required to reproduce any number in the results.

## The finding this benchmark is built to measure

In atomistic workflows the dominant agent failure is not a crash. It is the **silent
convention error**: the agent runs the right simulation, gets the right physics, and
then reports the number in eV instead of eV/atom, or on the conventional cell instead
of the primitive one, or unrelaxed instead of relaxed.

No exception is raised. Every syntactic check passes. The answer is confidently wrong
by an exact, identifiable factor.

A plain numeric check calls that "wrong" and stops. MatAgentBench calls it
`silent_basis`, states the factor, and shows the intervention that fixes it.

### How that is proven, not asserted

For any wrong answer, the reconciler searches a **closed set** of known convention
transforms — unit conversions, atom/formula-unit counts, primitive↔conventional cell
ratios, sign conventions, and bounded compositions of those. If exactly one carries the
agent's number onto ground truth within tolerance, the physics was right and the
bookkeeping was wrong.

This is mechanical. No LLM judge is involved anywhere in scoring.

The search space is bounded on purpose: an unbounded set of factors would "explain" any
number at all. `tests/test_reconciliation.py` tests both directions — that real
convention errors are caught, and that an arbitrary wrong value is **not** explained
away.

## Counterfactual attribution

A taxonomy says what a failure looked like. Attribution says what would have had to be
different for it to succeed.

For each failed trajectory we replay the recorded run verbatim up to step *k*, change
exactly one thing, and let the agent continue live:

| Intervention | What is changed at step *k* | What recovery implicates |
|---|---|---|
| `plan_repair` | Inject the reference stage sequence at step 0 | Planning, not execution |
| `context_restore` | Re-inject early observations at the midpoint | Long-horizon forgetting |
| `tool_repair` | Fix the first malformed call, nothing else | Tool-use mechanics |
| `convention_correct` | Restate required unit/basis/cell at the *final* step | Reporting, with all physics held fixed |

Because every counterfactual shares a prefix with its base run, the difference in
outcome is attributable to the intervention rather than to sampling. Replaying the
prefix is also what makes this affordable — only steps after the intervention cost
anything.

`convention_correct` is deliberately injected as late as possible. If a run recovers
when the convention is restated *after* all computation is complete, that is direct
evidence the simulation was correct and only the reporting was not.

## Benchmark integrity

Three design decisions that make the numbers mean something:

**Tasks are oracle-calibrated.** Ground truth comes from DFT; the agent's tools are an
ML potential. Those disagree by a real margin. A task whose tolerance is tighter than
that margin is unpassable no matter how good the agent is, and would pollute the
taxonomy with false `numeric_wrong`. So every task is generated by running the reference
workflow *with the agent's own tools* and kept only if the oracle passes. What survives
is a set where failure is attributable to the agent, not to the potential.

**Answers are withheld from the tools.** `mp_get_structure` strips
`formation_energy_per_atom`, `band_gap`, `density` and friends before the agent sees
them. If retrieval returned the DFT value, every task would collapse into a lookup.

**Unearned passes are tracked separately.** A correct value produced with no
corresponding tool calls is recorded as `unearned_pass` — recalled from pretraining,
not computed. `pass_rate` includes those; `earned_pass_rate` does not. Both are
published.

## Quick start

```bash
python -m venv .aaienv && .aaienv\Scripts\activate     # Windows
pip install -e ".[data,sim,dev]"

cp .env.example .env        # add MP_API_KEY + one free LLM key
mab doctor                  # shows exactly what is configured and what is missing
```

`mab doctor` is the intended first command — it reports which optional dependencies and
which free-tier providers are actually available before you spend time on a sweep.

```bash
mab gen-tasks --limit 60          # build + calibrate the task set
mab run --preset mid-open         # sweep trajectories (resumable, cached)
mab attribute --preset mid-open   # counterfactual interventions over failures
mab report                        # emit leaderboard.json + trajectory index
```

Every stage is safe to interrupt. Completed trajectories are checkpointed atomically and
skipped on resume, and every LLM response is cached by request hash — an overnight sweep
killed by a rate limit resumes for free.

### Requirements

- Python 3.11+
- A free [Materials Project](https://next-gen.materialsproject.org/api) API key
- At least one free LLM key (Groq / Cerebras / OpenRouter / HF), or a local Ollama server
- ~6 GB VRAM is comfortable for CHGNet on small cells; CPU works, just slower

## Layout

```
src/matagentbench/
  schema.py          canonical data model — everything else is a consumer
  units.py           convention reconciler (the core diagnostic)
  verify/            trajectory -> named failure class
  sim/               CHGNet workflows: relax, EOS, formation energy, defects
  data/              Materials Project + JARVIS-DFT ground truth, cached
  tasks/             task generation with oracle calibration
  agent/             backends, tools, prompts, resumable runner
  attribute/         counterfactual intervention harness
  report.py          aggregation into the JSON the site renders
site/                static leaderboard + trajectory viewer (GitHub Pages)
results/             committed JSON — the site reads these directly
```

## Task families

| Family | Tier | Ground truth | Workflow stages |
|---|---|---|---|
| `density` | 1 | Materials Project | fetch |
| `lattice_parameter` | 1 | oracle-calibrated | fetch → relax → cell |
| `relaxation_delta` | 2 | potential-defined | fetch → single-point → relax |
| `formation_energy` | 2 | MP, calibrated | fetch → relax → references → analysis |
| `bulk_modulus` | 2 | MP elasticity | fetch → relax → EOS fit |
| `polymorph_ranking` | 3 | potential-defined | 2× (fetch → relax) → analysis |
| `vacancy_formation` | 3 | potential-defined | fetch → supercell → defect → 2× relax → analysis |

Tier rises with the number of *dependent* stages — tier 3 tasks are where long-horizon
context degradation shows up.

## Adding a model

Every provider used here is OpenAI-chat-compatible, so adding one is a single row in
`agent/backends.py::PRESETS`. A text action protocol is used rather than native function
calling, because free-tier endpoints disagree about tool-call support — this keeps
differences in results attributable to models rather than to vendor plumbing.

Contributions of frontier-model runs are welcome; the harness is provider-agnostic.

## Limitations

- Ground truth is DFT (or the potential itself), and the agent's tools are an ML
  potential. Tolerances are calibrated to absorb that gap, but tight-tolerance physics
  is out of scope by construction.
- Results published here cover open-weight models on free tiers. Whether the same
  failure distribution holds for frontier models is **untested** — the harness is ready
  for anyone who wants to check.
- Attribution is a single-intervention design. Interacting causes are not disentangled.
